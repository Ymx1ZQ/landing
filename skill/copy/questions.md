# Discovery Questions (April Dunford style)

If the user has not provided the information below — via `value-proposition.md` or direct answers — ask for it. **Always** lead with a plausible draft answer drawn from the value proposition, then invite confirmation or correction. Do not ask open-ended questions.

### 1. The Problem and Status Quo (The Alternatives)
- **Question:** Who is the "enemy"? If the customer didn't buy you, what would they use today? (Often the competitor is a spreadsheet, an intern, a legacy tool, or "doing nothing" — not always a direct competitor.)
- *Why it's needed:* To position against the old way of doing things, not against specific features of a direct competitor.
- *Agent suggestion format:* "Based on the value proposition I'd guess the alternatives are <X> and <Y>. Is that right?"

### 2. The Insight (The Shift in Perspective)
- **Question:** What do you know about the problem that your customers (and competitors) ignore? What is the uncomfortable truth about how this problem is solved today?
- *Why it's needed:* To establish authority and earn immediate trust — "the old method no longer works because the market has shifted".
- *Agent suggestion format:* "Candidate insight from your POV: <draft>. Keep, sharpen, or replace?"

### 3. Differentiated Value (Feature → Benefit → Value)
- **Question:** What are the 3 "killer" features that only you have (or do better) — and what is the business value of each?
- *Required format:* `Feature → Advantage → Final Value` (e.g., "AI analysis" → "less time spent on data" → "strategic decisions in minutes, not days").
- *Agent suggestion format:* Propose 3 features clustered into 3 themed value buckets, each with its benefit → value chain. User accepts or reorganizes.

### 4. Social Proof (Proof)
- **Question:** Do you have numbers, client logos, awards, or statistics proving your solution works?
- *Agent suggestion format:* If the user does not have any, propose using "use cases" or "guarantees" instead, and write them out as candidates.

### 5. The Offer and CTA
- **Question:** What is the exact action the customer should take? (Demo, direct purchase, free trial.) Is there an irresistible offer or a money-back guarantee?
- *Agent suggestion format:* Propose one primary CTA and one secondary CTA (lower-commitment next step) for the hero. Ask the user to confirm or swap.

### 6. Primary Segment Confirmation
- **Question:** The `value-proposition.md` file identifies <Segment X> as the primary segment. Is this landing page still aimed specifically at <X>? If multiple segments are relevant, pick **one** for this artifact — secondary segments are noted for separate future runs.
- *Why it's needed:* Dunford's rule — one pitch, one segment. A landing page that tries to address multiple segments will serve none.
- *Agent suggestion format:* "I'll write the landing aimed at <X>. Confirm?"

### 7. Conversion Mechanism (Booking vs Contact)
- **Question:** What's the primary conversion on this page — a **scheduled call** (Calendly, SavvyCal, Cal.com, or similar) or a **contact form** (Formspree, HubSpot, Typeform, Tally, or custom backend)?
- *Why it's needed:* The copy for hero CTAs, the conversion section, and the FINAL CTA changes entirely based on this. Booking → *"Book a demo", "Pick a time"*. Contact → *"Get in touch", "We'll reply within 24h"*.
- *Agent suggestion format:* "Based on your value proposition and segment I'd guess <booking / contact>. Confirm, or switch?"
- *Downstream:* `/landing html` will ask you to paste the actual embed URL/HTML in FASE 0. This question is only about the *framing* the copy should adopt.
